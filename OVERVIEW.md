Workspace Ports adds a Ports tab to each workspace. See configured Paseo services and listening processes associated with the workspace directory, open apps in a Paseo browser tab, inspect details, and view logs or start and stop configured services.

For a workspace on another Mac, Open shows the destination and lets you choose the local port before connecting. After confirmation, an SSH tunnel runs in a Paseo terminal on your viewing Mac. Existing tunnels can be reused. Disconnect tunnel closes the forward without stopping the remote app; Stop app is a separate action for configured services.

Requires macOS and Paseo Desktop/daemons 0.14.x. Git installation also requires Node.js 22.13 or newer and npm on the daemon's command path. Installation runs the declared lockfile-based dependency preparation with dependency lifecycle scripts disabled, allowing Paseo's builder to resolve SDK/type packages. No software is downloaded during ordinary activation, discovery, or tunnel creation.

In Connection settings, choose the viewing Mac, an existing workspace on it for tunnel terminals, and an SSH alias or user@host that reaches the workspace Mac. SSH key authentication and known-host trust must already work. The alias is configurable; SSH reads the viewing Mac's own SSH configuration. The plugin does not collect passwords, create keys, or accept unknown host keys. For direct same-Mac browsing, select the workspace's own host and leave the SSH target empty.

Settings identify one viewing Mac per workspace host and are shared by that host's authorized Paseo clients. Both hosts must be connected in Paseo, and the viewing Mac needs a running daemon. Disconnect tunnels before changing the pairing. Closing the panel leaves tunnels running; stopping their terminals or daemon ends forwarding.

Plugins are trusted, unsandboxed code. This plugin reads process socket and working-directory information, starts and stops configured services, reads requested service logs, and creates tunnel terminals. Process details and logs pass through Paseo to the client. Browser traffic passes through the chosen SSH connection to the app. Settings store connection identifiers, not credentials. The plugin adds no analytics or model-provider calls.

To open an app on a phone or any device without SSH keys, choose Share. The plugin on the workspace Mac runs a foreground Tailscale Serve share in a Paseo terminal and gives you a tailnet-only HTTPS link to open or copy. Stop sharing closes the share without stopping the app; shares end with their terminal and don't survive a restart. This requires Tailscale with MagicDNS and HTTPS certificates on the workspace Mac and Tailscale on the device that opens the link. The first open can take up to a minute while Tailscale issues a certificate.

Detected entries show directory association, not proof of agent ownership or HTTP service. Only configured Paseo services have start/stop controls. Forwarding binds to localhost on the viewer and targets loopback on the workspace Mac; it does not change the app's own exposure or authenticate other local applications. HTTP URLs are supported; Docker discovery, phone-local SSH forwarding, public sharing (Tailscale Funnel), persistent shares, and automatic reconnection are not included. Apart from the tailnet-only shares you start, the plugin does not configure Tailscale.
